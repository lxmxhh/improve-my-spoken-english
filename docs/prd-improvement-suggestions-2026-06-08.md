# PRD 改进建议

**Date:** 2026-06-08
**Based on:** [2026-05-25-english-speaking-practice-design.md](superpowers/specs/2026-05-25-english-speaking-practice-design.md)

---

## 一、核心产品功能缺失

### 1. 缺少连读、弱读、语调等高级发音指导

**问题：** 用户的核心需求包括"纠正发音、熟练度、连读等问题"，但当前 PRD 中：

- 没有连读（linking sounds）的检测与教学
- 没有弱读（weak forms）的指导
- 没有语调（intonation）分析（升调、降调、升降调）
- 没有重音（stress）模式的教学（单词重音、句子重音）
- 没有语速（speech rate）的评估与指导

Azure Pronunciation Assessment 提供了音素级别的评分，但 PRD 没有设计如何将这些数据转化为**可操作的发音改进建议**。

**建议：**

- 增加连读检测：识别用户应该在哪些位置做连读但没有做
- 增加语调可视化：用图形展示用户语调与标准语调的差异
- 增加重音标注：在参考文本上标注重音位置
- 增加 `/api/pronunciation-coach` 的深度利用：基于 Azure 的 word-level 数据生成具体的发音改进建议（当前已有此 API 但未充分利用）

### 2. 对话模式过于固定

**问题：** 当前是"照本宣科"模式——AI 生成完整脚本，用户逐行跟读。这不是真正的"对话"，更像是朗读练习。

**建议：**

- 增加**自由对话模式**：AI 教练根据场景提问，用户自由回答（不限定参考文本），AI 评估语义合理性
- 增加**分支对话**：根据用户的回答动态调整下一句，而不是固定脚本
- 当前脚本只有 8 轮对话，太短，无法模拟真实场景的深度交流

### 3. 缺少难度分级和自适应

**问题：** PRD 提到目标用户是 B1-B2 水平，但没有：

- 用户初始水平评估
- 根据用户表现动态调整难度（词汇复杂度、语速、句子长度）
- 不同难度等级的脚本区分

### 4. 场景类型有限

**问题：** 只有 4 个分类（Daily Life / Work & Career / News & Society / Entertainment & Culture），缺少：

- 旅行场景（机场、酒店、问路）
- 商务场景（会议、谈判、演示）
- 社交场景（聚会、约会、闲聊）
- 紧急场景（看医生、报警、投诉）
- 用户自定义话题

## 二、发音评估与反馈

### 5. 发音反馈不够细致

**问题：** Azure 提供了音素级别的评分，但当前 UI 只展示 4 个维度的分数（pronunciation / accuracy / fluency / completeness），缺少：

- **音素级别的可视化**：哪些音素发错了，正确的口型/舌位提示
- **连读检测与指导**：英语中大量的连读现象（linking sounds）没有覆盖
- **重音和语调分析**：单词重音、句子重音、升降调
- **节奏分析**：停顿位置是否合理，语速是否均匀

### 6. Practice/Assessment 模式的用户体验不清晰

**问题：** 虽然设计了两种模式，但：

- 用户可能不理解两种模式的区别
- 没有引导用户何时使用哪种模式
- Assessment 模式的分数可能打击用户积极性，缺少正向引导

## 三、学习体验与记忆

### 7. 词汇学习缺乏复习机制

**问题：** 每次 session 结束会生成 3-5 个新词汇，但：

- 没有**间隔重复**（Spaced Repetition）系统
- 词汇只展示一次，用户很容易遗忘
- 没有词汇发音练习（点击单词听发音、跟读）
- 没有词汇使用场景的回顾

### 8. 缺少错误本和薄弱点追踪

**问题：** 用户反复犯的错误没有被系统性记录和分析：

- 没有**错误本**（Error Book）功能：记录用户反复说错的句子/单词/音素
- 没有**薄弱点分析**：比如 "你经常在 /θ/ 和 /s/ 之间混淆"
- 没有针对性的**强化练习**：基于错误分析生成专项练习

### 9. 学习数据可视化不足

**问题：** `/history` 页面只有简单的 session 列表，缺少：

- 发音分数趋势图（折线图展示 pronunciation score 变化）
- 各类别话题的掌握程度
- 每周/每月的练习时长统计
- 常见错误 Top N 分析

## 四、产品体验

### 10. 每日 3 个话题的目标可能不合理

**问题：** PRD 设定每天 3 个话题（~15 分钟），但：

- 对于初学者可能太多，容易放弃
- 对于高级用户可能太少，不够挑战
- 建议改为**可配置的每日目标**（时间或话题数）

### 11. 缺少热身和冷却环节

**问题：** 直接进入对话太突兀：

- 没有**发音热身**：比如 tongue twister、音素练习
- 没有**听力预热**：先听一遍对话再跟读
- 没有**回顾上次内容**：快速回顾昨天的词汇和错误

### 12. 没有社交和激励机制

**问题：** 虽然有 streak 和 daily goal，但：

- 没有成就系统（badges/achievements）
- 没有长期目标设定（比如 "30 天连续打卡"）
- 没有分享功能

## 五、技术架构

### 13. localStorage 的局限性

**问题：** 所有数据存在 localStorage：

- 清除浏览器数据就丢失
- 无法跨设备同步
- 存储容量有限（~5MB）
- Android 迁移计划虽然提到了 Capacitor 方案，但长期来看需要后端数据库

### 14. 缺少离线支持

**问题：** 完全依赖网络：

- 没有网络时无法练习
- 可以考虑缓存常用脚本、预下载 TTS 音频

## 六、优先级建议

| 优先级 | 改进项 | 理由 |
|---|---|---|
| 🔴 P0 | 连读/弱读/语调指导 | 用户明确提到需要纠正连读问题，这是核心差异化价值 |
| 🔴 P0 | 自由对话模式 | 这是"口语练习"的核心价值，当前只是朗读练习 |
| 🟡 P1 | 间隔重复词汇复习 | 学了不复习等于没学 |
| 🟡 P1 | 错误本 + 薄弱点分析 | 针对性改进比泛泛练习有效得多 |
| 🟡 P1 | 难度分级和自适应 | 不同水平的用户体验差异大 |
| 🟢 P2 | 丰富场景类型 | 当前 4 个分类太少 |
| 🟢 P2 | 学习数据可视化 | 帮助用户看到进步 |
| 🟢 P2 | 可配置的每日目标 | 更灵活 |
| ⚪ P3 | 发音热身/冷却 | 锦上添花 |
| ⚪ P3 | 成就系统 | 激励但非核心 |

---

## 七、总结

当前项目的基础架构（录音→转写→评估→反馈）已经搭建得不错，但核心问题在于：

1. **产品形态偏向"朗读跟读"而非"真实对话"**——用户只是在读固定脚本，没有真正的口语输出
2. **缺乏系统性的发音纠正反馈**——连读、语调、音素指导等高级发音教学缺失
3. **缺乏学习记忆机制**——间隔重复、错误本等帮助长期记忆的功能缺失

建议优先解决 P0 级别的改进，让产品真正成为"口语练习"工具而非"朗读练习"工具。
